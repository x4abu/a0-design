# Frontend design (Anthropic skill, distilled)

Source: anthropics/skills → skills/frontend-design/SKILL.md (Apache-2.0 per skill).
Use: the aesthetic-direction pass that runs before any code is written.

Core idea: act as the design lead of a studio known for giving every client a
distinct identity. The client has already rejected templated proposals.

How to apply it in a0:
1. Ground the design in the subject matter. A coffee app and a budgeting app must
   not share a visual language. If the brief doesn't name the subject, name one.
2. Write a compact plan first — 4–6 named hex values, the typefaces and their
   roles, one-sentence layout concept, and the principles that make it specific.
3. Review the plan against the brief before building: if any part of it is what you
   would produce for any similar page, revise that part and say what changed.
4. Spend boldness in one place. One memorable element; everything else quiet.
5. Type carries personality: one or two clearly distinct families, a deliberate
   scale, line lengths under 80 characters.
6. Avoid these generated-page tells: a single accented word in a headline, all-caps
   labels, eyebrows above every heading, meta strings joined with middle dots,
   a monospace face for small labels, "→" appended to every link.
7. Motion: one orchestrated moment (a load sequence or a reveal) beats scattered
   fade-and-slide-ups on every section.
8. Copy is design content. Name things the way users understand them; a CTA says
   exactly what happens ("Save changes", not "Submit"); errors explain the fix.
9. Self-critique as you build. Chanel's rule: before leaving the house, remove one
   accessory.
