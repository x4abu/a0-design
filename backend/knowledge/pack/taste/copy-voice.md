# Copy voice

Copy is the cheapest premium signal and the one models fumble most. These rules are
testable.

## Voice
- Plain verbs, sentence case, active voice, no filler.
- One job per line. If a sentence has two jobs, it becomes two lines or one is cut.
- Speak about the user's world, not the system's internals: "your designs", not "artifacts".
- Confident, not salesy. No superlatives, no "seamlessly", no "unlock", no "revolutionise".

## Naming
- Name things by what the user controls, not how it is built: "Notifications", not
  "Webhook configuration".
- The same action keeps the same name through the whole flow: the button says "Publish",
  the toast says "Published", the empty state says "Nothing published yet".
- A CTA names the outcome: "Start a design", "Add API key", "Save changes" — never
  "Submit", "Continue" or "Get started".

## Microcopy patterns
| Situation | Shape |
|---|---|
| Empty state | what belongs here + why it's empty + one action |
| Error | what happened + how to fix it (never "Something went wrong") |
| Loading > 2s | what is happening, in the user's terms |
| Destructive confirm | the consequence, the object, and the escape |
| Permission prompt | the benefit first, the request second |
| Success | the result, in one line, no exclamation marks |

## Banned strings
`lorem ipsum`, `your text here`, `feature one/two/three`, `sample content`, `placeholder`,
`Welcome to <product>`, `Your all-in-one solution`, `Unlock the power of`,
`Take your X to the next level`, `Seamlessly integrate`.

## Numbers and claims
Every number must be real and sourced, or clearly a placeholder the user must replace.
Invented metrics ("10× faster", "99.9% uptime", "trusted by 10,000 teams") are a hard fail.

## Test
Read the copy aloud. If a sentence could appear in any other product's onboarding, rewrite
it until it could only be yours.
