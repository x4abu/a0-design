# Laws of UX as build rules

Adapted from OpenDesign's `craft/laws-of-ux.md` (Apache-2.0). Each law turned into a
check you can run on a screen.

| Law | Rule for the build |
|---|---|
| **Hick** | ≤ 5 primary choices per screen; group the rest behind one "more" affordance |
| **Fitts** | primary action is large (≥48dp), in the thumb zone, ≥8dp from neighbours |
| **Miller** | chunk content into 3–5 groups; never present 12 equal options |
| **Jakob** | follow platform convention (back, sheets, nav) — originality lives in style, not in moving the close button |
| **Aesthetic-usability** | polish earns patience: the first screen must look finished before it asks for anything |
| **Von Restorff** | exactly one element should be visually distinct per screen |
| **Doherty** | feedback inside 400 ms (target 100 ms); optimistic UI for anything slower |
| **Peak-end** | the success moment and the exit are what people remember — design both |
| **Serial position** | first and last items in a list get attention; put the important one there |
| **Tesler** | complexity has to live somewhere — absorb it in defaults, not in the user's face |
| **Goal-gradient** | show progress once the user has started; near-completion messaging works |
| **Zeigarnik** | incomplete states should be resumable and visible, not hidden in a menu |
